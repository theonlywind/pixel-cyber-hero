# 老師後台（Google Apps Script + Google Sheet）

學生玩遊戲時，會自動將「課堂代號、佢輸入嘅名、關卡、星數」上報去你嘅 Google Sheet；老師開後台網頁就睇到每個學生嘅完成紀錄。免費，唔使自己部伺服器。

## 設定（約 10 分鐘，只做一次）

1. 開一個新嘅 **Google Sheet**（名隨便，例如「網絡安全小勇者紀錄」）。
2. 選單 **擴充功能 → Apps Script**。
3. 將 `Code.gs` 全部內容貼入編輯器（取代預設嘅 `Code.gs`）。
4. 左邊 **＋ → HTML**，檔名輸入 `admin`，將 `admin.html` 全部內容貼入。
5. 設定老師密碼：左邊 **專案設定（齒輪）→ 指令碼屬性 → 新增**，名稱 `ADMIN_PASS`，值係你自己嘅密碼。
6. 右上 **部署 → 新增部署作業 → 類型：網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**所有人**（學生唔使登入 Google）
   - 按部署，授權後會得到一條 `https://script.google.com/macros/s/…/exec` 網址。
7. 將呢條網址貼入遊戲嘅 `config.js`：
   ```js
   window.REPORT_URL = 'https://script.google.com/macros/s/…/exec';
   ```
   然後 push 到 GitHub。
8. 老師後台：直接開同一條 `/exec` 網址，輸入 `ADMIN_PASS`。

> 之後如果改咗 `Code.gs` 或 `admin.html`，要 **部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署**，網址唔變，但要新版本先會生效。

## 每堂課點用

1. 老師開後台，**「開新課堂」**（備註可寫「3A 第 2 堂」，只係方便自己認，可留空），按「產生課堂代號」，得到 4 位代號（如 `K7P2`）。
2. 老師將代號寫喺黑板／投影出嚟。
3. 學生喺遊戲標題畫面輸入自己嘅**名**同**課堂代號**，按「開始冒險」。
4. 下課後，老師按「結束課堂」。之後有人再用呢個代號，會被拒絕（遊戲會提示「課堂代號不正確，或者課堂已經結束」）。

- 學生唔填課堂代號都可以玩，但唔會上報。
- 後台**唔記班別、唔記座號**，每個課堂代號就係一組學生，學生以佢輸入嘅名顯示。同一堂有兩個同名學生（例如兩個「小明」），會因為各自裝置嘅隨機代號而分開顯示；同一個學生用唔同名，會被當成兩個人。
- 網絡有問題時，遊戲照玩，紀錄會排隊，稍後補送；補送時如果課堂已經結束，就會被拒絕。
- 由舊版（含班別欄）升級嘅話：第一次運行時，舊嘅 `records`、`sessions` 工作表會自動改名做 `…_舊版_日期`，另開新表，舊資料唔會刪。

## 上報咗啲乜

| 事件 | 時機 | 內容 |
|---|---|---|
| `start` | 學生按「開始冒險」 | 課堂代號、名、年級 |
| `level` | 過關 | 關卡、星數、答錯次數 |
| `fail` | HP 用完 | 關卡 |
| `boss` | 黑客熊挑戰結束 | 是否通過、答對題數 |
| `cert` | 第一次領證書 | 證書編號 |

- 資料寫入 Sheet 嘅 `records`（每個事件一行）同 `sessions`（課堂）工作表，老師亦可以直接用 Sheet 篩選、做圖表。
- **會收集學生喺遊戲輸入嘅名**（最多 8 字），另加每部裝置一個隨機代號（只係用嚟分開同名玩家）。**建議叫學生用暱稱或學號，唔好用全名。**

## 私隱同限制（請留意）

- 資料存喺你嘅 Google 帳戶，請按學校政策處理，並建議先向家長／學校說明收集範圍。
- 上報網址要「所有人」可存取，但後台只接受**仍然開放嘅課堂代號**嘅資料，亦只收格式正確嘅事件。課堂結束後，亂送資料會被拒絕；課堂進行中，知道代號嘅人（包括同學）仍然可以用別人嘅名送假紀錄，所以呢啲紀錄適合課堂參考，唔適合做正式評分。
- 遊戲進度仍然存喺**每部裝置嘅瀏覽器**。如果幾個學生共用一部 iPad，本機進度會混埋；後台紀錄就係按各自輸入嘅學號分開。想避免，叫學生用「重新開始」或每人用自己裝置。
- 上報失敗（冇網絡）會排隊，下次開遊戲或恢復網絡時自動補送；但如果 Google 收到之後拒絕，遊戲睇唔到結果（`no-cors` 限制）。
- `config.js` 留空（預設）嘅話，遊戲完全唔上報，標題畫面亦唔會出現「課堂代號」欄。
